Privacy Policy for AMTA Lexicography Assistant

Last Updated: November 2026

The AMTA Lexicography Assistant is an academic research tool designed to prioritize user data privacy and adhere strictly to Google's User Data Policy. This policy explains what data the Add-on accesses, how it is used, and confirms what data is not collected.

DATA MINIMIZATION AND CORE PRINCIPLE

The Add-on is designed to process data ephemerally to run its core functions. We DO NOT collect, store, share, or sell any Personal Identifiable Information (PII), sensitive user data, or your email address for any secondary purpose.

1. Google Workspace Data Access (Scopes Used)

The AMTA Lexicography Assistant requests access to the following scopes to perform its core function: the automated data pipeline for dictionary compilation. Access is strictly limited to the necessary functions described below:

  • Google Drive Access: https://www.googleapis.com/auth/drive.file

    Justification: Used solely to read user-specified reference corpus JSON files explicitly uploaded via the Sidebar, and to save the final exported dictionary files (XML/CSV/JSON) directly into your Drive. Access is strictly confined to files created or opened by this Add-on.

  • Google Sheets Access: https://www.googleapis.com/auth/spreadsheets.currentonly

    Justification: The application reads and writes data strictly within the active spreadsheet where the Add-on is invoked. This is necessary to retrieve headwords and write back definitions, keyness statistics, citations, and collocations.

  • Apps Script Triggers: https://www.googleapis.com/auth/script.scriptapp

    Justification: Used solely to manage temporary, one-time continuation triggers that overcome Apps Script's 6-minute execution quota during large-batch dictionary generation. Triggers self-delete immediately upon execution.

MANDATORY LIMITED USE DISCLOSURE (INCLUDING AI RESTRICTIONS):

The AMTA Lexicography Assistant's use and transfer of information received from Google APIs to any other app will adhere to the Google Workspace API User Data and Developer Policy, including the Limited Use requirements.

Specifically, Google Workspace user data (including raw, aggregated, or derived data from Google Sheets or Drive) is never used, transferred, or sold to create, train, or improve foundational or generalized machine learning and artificial intelligence models. Data is utilized strictly to provide user-facing lexicographical features within the Add-on.

2. Third-Party Data Processing & AI Model Integrations

To generate definitions, tag parts of speech, and extract academic references, the Add-on connects via secure HTTPS to the following AI and literature research APIs using user-supplied credentials (BYOK) or open endpoints:

  • Google Gemini API: Used for technical definition drafting, semantic evaluation, and multilingual translation.
  • Groq Cloud API: Used as an optional high-speed inference fallback provider for collocation and definition generation.
  • Hugging Face Inference API: Used strictly for discrete Part-of-Speech (POS) classification using a pre-trained encoder model.
  • LM Studio (Strictly Self-Hosted / Offline): Provides an optional local model connection running on the user's isolated hardware over a local or tunneled HTTPS endpoint.
  • Academic Literature APIs (Semantic Scholar, OpenAlex, arXiv, Europe PMC, CORE, Scopus, SerpApi): Used purely as bibliographic search engines to retrieve paper titles, citation counts, and abstracts. These do not train generative models.

2.1 Strict Prohibition on AI Model Training & Self-Hosted Disclosures

ZERO MODEL TRAINING & LOCAL PROCESSING COMMITMENT

  • No Foundational AI Training: No Google user data processed by this Add-on is used to train, retrain, fine-tune, or improve generalized AI/ML models.
  • Third-Party Cloud APIs: API calls to Google Gemini, Groq Cloud, and Hugging Face are executed under developer API terms that strictly process payloads in-memory and prohibit utilizing customer API inputs/outputs for foundational model training.
  • Self-Hosted / Offline Models (LM Studio): When the user selects LM Studio or a local model server, all inference is conducted strictly offline within the user's isolated infrastructure. Google user data is processed in local RAM and is never transmitted to LM Studio, model creators, or third parties for model training or secondary purposes.

3. Data Storage & PII

The developer (Dr. Waleed Mandour) maintains a strict data policy:

  • No External Storage: We do not store any of your Google Workspace data (file contents, email addresses, usage history, etc.) on any external database or server controlled by the developer. All API keys remain isolated in your personal Google account's UserProperties.
  • No PII Collection: The Add-on does not collect or track any Personal Identifiable Information (PII) for advertising, market research, or any purpose unrelated to the function of the Add-on.

4. Data Security & Protection Mechanisms

We employ industry-standard security measures to protect your data:

  • Encryption in Transit: All data transmitted between your Google Sheet and external APIs is encrypted using HTTPS (TLS 1.2/1.3) protocols.
  • Google Infrastructure: The Add-on's logic is hosted entirely on Google's secure Apps Script servers. We do not maintain separate external servers, databases, or cloud storage buckets for this application.

5. Data Retention and Deletion Policy

The AMTA Lexicography Assistant operates on a non-retention basis:

  • Ephemeral Processing: Data retrieved from your spreadsheet is processed in the volatile memory of the script runtime and discarded immediately upon completion. We do not retain query logs or cell contents.
  • Data Deletion: Since we do not store your data on external servers, there is no user data to delete from our side.
  • User Control: You maintain full ownership of your data. To permanently delete data processed by the Add-on, simply delete the contents from your Google Sheet or Google Drive.

6. User Consent and Contact

By installing and using this add-on, you consent to the data processing methods described in this policy, acknowledging its strict adherence to research-only usage principles.

لتوليد التعريفات وتصنيف أقسام الكلام واسترجاع المراجع، تتصل الإضافة عبر بروتوكول HTTPS الآمن بواجهات برمجة التطبيقات التالية:

  • Google Gemini API: يُستخدم لصياغة التعريفات التقنية والتقييم الدلالي والترجمة متعددة اللغات.
  • Groq Cloud API: يُستخدم كخيار بديل عالي السرعة لتوليد المتصاحبات اللفظية والتعريفات.
  • Hugging Face Inference API: يُستخدم لتصنيف أقسام الكلام (POS) باستخدام نموذج تشفير مدرّب مسبقاً.
  • LM Studio (المستضاف ذاتياً / بدون إنترنت): يتيح ربط نماذج الذكاء الاصطناعي المحلية التي تعمل بالكامل داخل جهاز المستخدم.
